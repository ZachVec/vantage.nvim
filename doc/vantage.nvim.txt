1. INTRODUCTION                                *vantage.nvim-introduction*

Vantage is a coding-agent manager for Neovim. It runs coding agents (Claude
Code, Codex, dsh, …) in a tmux server and shows them in a single persistent
`:terminal`. tmux is the state store, multiplexer, renderer and input layer —
there is no custom TUI.

The plugin owns the backend: its Lua layer drives a private tmux socket
directly. The frontend is a pluggable picker (native / fzf-lua / snacks) plus
the terminal window that is the tmux client.
Each Neovim instance attaches through its own tmux view, so two instances can
show different Agents from the same Group without moving each other.

==============================================================================
2. REQUIREMENTS                                *vantage.nvim-requirements*

- Neovim >= 0.10
- tmux 3.0+ (developed against 3.6a)
- nvim-treesitter-textobjects (optional; for the `{function}` / `{class}`
  prompt placeholders)

==============================================================================
3. INSTALLATION                                *vantage.nvim-installation*

Install with your favorite package manager. With lazy.nvim: >

    {
      "ZachVec/vantage.nvim",
      cmd  = "Vantage",
      opts = {},
    }

<

lazy.nvim resolves the module name `vantage` from the repo and runs
`require("vantage").setup(opts)` automatically. The plugin loads lazily on the
first `:Vantage`.

4. CONFIGURATION                              *vantage.nvim-configuration*

`setup()` accepts: >

    require("vantage").setup({
      backend = "tmux",          -- pluggable backend driver (only "tmux" today)
      socket  = "vantage",       -- private tmux socket name
      picker  = "native",        -- native | fzf-lua | snacks
      prompts = {              -- {file}/{line}/{reviews} built in; add/override yours
        ["{file}"] = "{file}",
        ["{line}"] = "{line}",
        ["{reviews}"] = "{reviews}",
      },
      reviews = {              -- notes on line ranges, sent via {reviews}
        item = "{lines} {note}",  -- per-review template
        clear_on_send = true,     -- clear after a sent prompt uses {reviews}
        float = {                 -- note-float window options
          style = "inherit",      -- "inherit" (default) | "minimal"
        },
      },
      cli = {
        tools = {},              -- provide your own (name -> cmd array); nothing built in
        win = {                  -- the terminal window that is the tmux client
          layout = "float",      -- float | full | left | top | bottom | right
          float  = { width = 1.0, height = 1.0, border = "none" },
          split  = { width = 80, height = 20 },
          keys = {},             -- no keymaps by default; add your own
        },
      },
    })

<

`backend` and `picker` are validated during `setup()`. An unknown name, an
unavailable implementation, or a missing picker dependency raises an error
instead of silently falling back.

The default `layout = "float"` opens the terminal as a borderless floating
window at the full editor size — a pure terminal view, with no statusline,
winbar, or border. If the terminal's cursor flickers for you, use
`layout = "full"` (a dedicated tab) instead. The float's `width`/`height` are
fractions of the editor area (0 < v <= 1).

The Agent pane draws a top tmux border showing the Group, the Agent's Tool,
its working directory — absolute path, `~` for the home prefix — and the
Group's State counts (running / background / waiting / idle / error, non-zero
buckets only, shown as Nerd Font icons). It refreshes about once a second,
is always on and not configurable.

`cli.tools` is empty by default — provide every tool yourself, e.g. `tools = {
claude = { cmd = { "claude" } } }`. `tools.<name>.cmd` is an argv array: each
element is shell-quoted before the Agent's shell runs it, so arguments keep
their boundaries. It may include arguments, e.g.
`{ cmd = { "claude", "--dangerously-skip-permissions" } }`. Nothing is built
in. A tool entry needs a non-empty name, a non-empty `cmd` array, and a first
element that is executable on PATH — entries that fail any of these are
dropped at setup with a warning and listed by `:checkhealth vantage`. A tool
may also carry a `format` function (`fun(text): string`), applied to a
rendered prompt just before it is sent to the Agent.

PROMPT TEMPLATES ~

`prompts` maps names to text templates. Three are built in — `{file}`, `{line}`,
and `{reviews}`, as identity templates (`"{file}"` → `"{file}"`) — so the raw
location references and the accumulated Reviews are always available. The
`{reviews}` prompt is hidden while there are no Reviews. The `prompt` key (see
TERMINAL FILETYPE & KEYMAPS) picks one through the pluggable Picker's
plain-select form and pastes it into the focused Agent's input (no
auto-submit). Your `prompts` merge additively: a name you set overrides the
built-in, and names you leave unset are kept. A template may use five
placeholders, four of which are Claude-style location references relative to
the Agent's cwd:

  `{file}`         `@path/to/file.lua`
  `{line}`         `@path/to/file.lua :L42` (cursor line)
  `{function}`     `function foo @path/to/file.lua :L42:C3`
  `{class}`        `class Foo @path/to/file.lua :L42:C3`
  `{reviews}`      every Review, each rendered by `reviews.item`

`{function}` and `{class}` need nvim-treesitter-textobjects; without it (or
outside a function/class) the prompt is skipped with a warning — that is why
they are not built in. An unknown placeholder is left literal at runtime and
reported by `:checkhealth`. A prompt may span multiple lines; newlines are
typed literally and never submit. Examples: >

    require("vantage").setup({
      prompts = {
        review    = "Review {file} for issues.",
        fix_line  = "Fix {line}.",
        document  = "Add documentation to {function}.",
      },
    })

<

An Agent's working directory is Neovim's global cwd (it follows `:cd`;
`:lcd`/`:tcd` do not affect it).

REVIEWS ~

A Review is a note anchored to a line range in a normal file. Add one with
`:Vantage review` (over the visual selection, else the current line);
`:Vantage review list` opens a picker of reviews — selecting one jumps to its
range and opens an editable note float. `:Vantage review clear` removes every
review. Reviews tint the range's line numbers only — no sign column, no layout
shift, no code obscuring; when the number column is off they are not drawn.
They live in memory only: lost on buffer unload/reload or Neovim exit, and
never written to the file.

The note float is a normal scratch buffer (normal mode), so editing is ordinary
Vim — multi-line notes and undo included. By default
(`reviews.float.style = "inherit"`) its window options follow the window it
opens from; set `reviews.float.style = "minimal"` for a clean dialog look with
those options off. Pressing `<Esc>` commits the note and closes the float; an
empty note deletes the review after a confirmation.

The picker is the pluggable one (`native` / `fzf-lua` / `snacks`): fzf-lua and
snacks preview each review through `reviews.item` (what you see is what gets
sent) and offer an in-place `<c-x>` delete; native is selection only.

Send the accumulated reviews to the focused Agent through a Prompt that uses
`{reviews}`, e.g. `prompts = { notes = "My notes:\n{reviews}" }`.
`reviews.item` is the per-review template; its fields are:

  `{note}`    the review text
  `{lines}`   `@path/to/file.lua :L10-L20` (`:L10` for a single line)
  `{code}`    the selected lines, leading/trailing blank lines dropped
  `{file}`    the relative path (no `@`, no `:L`)
  `{start}`   the first line number
  `{end}`     the last line number

The default `item` is `"{lines} {note}"`; to also send the code use
`item = "{lines} {note}\n{code}"`. When `clear_on_send` is true (default), a
successful send whose template used `{reviews}` clears all reviews.

PICKERS ~

Agent rows in the Agent picker (the `switch` key, or `:Vantage toggle` with no
terminal) are sorted by group, working directory, and tool name; when the list
is opened from the terminal window, the Agent that terminal shows is pinned to
the top with a `(focused)` marker, and confirming that row does nothing. When
no Agent is running and no tool is configured, the picker warns instead of
opening.

The Agent list (the `switch` key), the kill list (`:Vantage kill`), and the
review list go through a pluggable picker, chosen by `picker`:

  `picker = "native"`   built-in `vim.ui.select` (default). Respects any
                        global `vim.ui.select` override (dressing.nvim,
                        snacks' ui_select, …).
  `picker = "fzf-lua"`  fzf-lua; requires the fzf-lua plugin.
  `picker = "snacks"`   snacks.nvim picker; requires snacks.nvim.

`fzf-lua` and `snacks` preview the selected Agent's pane (its recent terminal
output). The Agent list opens scoped to the focused Agent's Group by default —
`<c-g>` toggles it in place (Tool rows always stay; with nothing focused the
whole list shows). The review list offers an in-place `<c-x>` delete. The
Agent-creation Group step and the `prompt` key run through the same picker in
its compact plain-select form. Free-text prompts (e.g. the new-Group name) use
`input()` and are insert-mode by default; Yes/No confirmations use Neovim's
built-in confirm dialog.

TERMINAL FILETYPE & KEYMAPS ~

No keymaps are added by default. The terminal buffer has filetype
`vantage_terminal`. Add keys in either of two ways:

1. `cli.win.keys` — a list of 4-tuples `{ lhs, rhs, mode = "n", desc }`,
   applied buffer-locally to the terminal when it is created. `rhs` is passed
   verbatim to `vim.keymap.set` — a key sequence / `<cmd>` RHS, or a Lua
   function — except a string naming a built-in terminal action, which runs
   that action. `mode` is `"n"`, `"t"` or `"nt"` (also a table). The built-in
   actions:

     `"switch"`  re-point the terminal to an Agent (Agent picker)
     `"prompt"`  pick a prompt and type it into the focused Agent
     `"toggle"`  hide/show the terminal

   `switch` and `prompt` are terminal actions only — there is no `:Vantage`
   command for them; bind them here. Example: >

      require("vantage").setup({
        cli = {
          win = {
            keys = {
              { "<c-q>", "toggle", mode = "t", desc = "hide/show the terminal" },
              { "q", "toggle", mode = "n", desc = "hide/show the terminal" },
              { "s", "switch", mode = "n", desc = "switch Agent" },
              { "p", "prompt", mode = "n", desc = "send a prompt" },
            },
          },
        },
      })

<

2. Any `ftplugin`/`autocmd` on the filetype (full control, plain
   `vim.keymap.set`): >

      vim.api.nvim_create_autocmd("FileType", {
        pattern = "vantage_terminal",
        callback = function(ev)
          vim.keymap.set("n", "q", ":Vantage toggle<CR>", { buffer = ev.buf })
          vim.keymap.set("t", "<c-q>", "<cmd>Vantage toggle<CR>", { buffer = ev.buf })
        end,
      })

<

For a normal-mode keymap that opens/toggles from anywhere in nvim (not just
inside the terminal buffer): >

      vim.keymap.set("n", "<leader>vt", "<cmd>Vantage toggle<CR>", { desc = "Toggle Vantage" })

<

==============================================================================
5. COMMANDS                                    *vantage.nvim-commands*

                                                          *:Vantage*
`:Vantage`
    Show help (no default action).

`:Vantage toggle`
    Hide the terminal window if it is open, or show it again — a lightweight
    toggle that keeps the buffer and the tmux client alive. If there is no
    live terminal, open the Agent picker (Agents plus one Tool row per
    configured `cli.tools` key) and open the terminal on the chosen Agent.

`:Vantage detach`
    Destroy the terminal window and detach its client. Agents keep running.

`:Vantage review`
    Add a Review over the command's range — a visual selection, or the current
    line when none — and open an empty note float.

`:Vantage review list`
    Open the Review picker (pluggable; fzf-lua/snacks preview each note and
    offer an in-place `<c-x>` delete). Selecting one jumps to its range and
    opens an editable note float.

`:Vantage review clear`
    Remove every Review (after a confirmation).

`:Vantage kill`
    Open the kill picker — one row per Agent, then one per Group — and kill
    the chosen Agent or Group.

`:Vantage status`
    Show attached clients and sessions (debug).

6. KEY CONCEPTS                                  *vantage.nvim-concepts*

Group ~
    A durable container of collaborating Agents, created when an Agent is
    created in it. It survives with nothing attached, and ends when its last
    Agent dies or it is killed.

Agent ~
    A running coding agent in a working directory, shared across a Group. It
    lives until killed or it exits on its own; closing the terminal never
    kills it.

Terminal ~
    The single `:terminal` that is Vantage's display surface (one per Neovim
    instance). Its existence is the attachment's existence: hiding it keeps
    the attached client alive, and destroying it (or the client exiting)
    detaches while the Agents keep running.

Review ~
    A note anchored to a line range in a normal file, kept in memory only and
    batched into the focused Agent through the `{reviews}` prompt placeholder.

State ~
    A transient condition of an Agent — running, background, waiting, idle,
    error (a fixed vocabulary). Written by the Agent's lifecycle scripts and
    aggregated per Group by the plugin's counting scripts; an Agent that has
    not reported yet counts as idle.
