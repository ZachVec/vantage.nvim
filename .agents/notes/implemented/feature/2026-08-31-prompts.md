# Agent Note: Prompts — named templates typed into a focused Agent

Status: implemented

## Problem

Agents are interactive REPLs: the only way to get context (current file, line,
function, class) into one is to type it. There was no way to recall a canned
message — every question had to be retyped by hand. sidekick.nvim solves this
with named prompt templates selected from a picker; Vantage wanted the same,
scoped to "select a prompt and type it into the focused Agent's input".

## Decision

`prompts` is a top-level `setup` table mapping names to string templates, with
three built-in identity defaults `{file}` → `{file}`, `{line}` → `{line}`, and
`{reviews}` → `{reviews}`; `cli.tools` remains empty. The `prompt` terminal
action — a `cli.win.keys` token, not a `:Vantage` subcommand — chooses one
through the Picker's plain-select form (`Picker.pick_naive`, since there is
nothing to preview); the chosen template is rendered and
pasted into the focused Agent's pane via a new Backend method
`send_keys(target, text)` — a bracketed paste (`set-buffer` + `paste-buffer -p`),
with no Enter, so the user reviews before submitting. Bracketed paste (not
`send-keys -l`) is required: claude collapses bare LF onto one line. The
focused Agent is the Attachment's `focus()` (the View the Terminal's client
sits on).

Two location placeholders, relative to the focused Agent's cwd: `{file}` (a
whole-file reference) and `{line}` (a `:L<row>` reference), each spelled
through the Tool's `format(file, loc)` hook — the default renders the path plus
a space-separated `loc`, and a Claude dialect is one hook
([tool-format-location-hook](2026-09-11-tool-format-location-hook.md)). A
`{function}` / `{class}` pair resolving nvim-treesitter-textobjects'
  `@function.outer` / `@class.outer` was later removed
  ([removal note](../simplification/2026-09-11-remove-function-class-prompt-placeholders.md)).
Context comes from the most-recently-visited non-terminal window (a `WinEnter`
stamp). A placeholder that resolves empty skips the send with a warning;
unknown placeholders are left literal at runtime and warned about by
`Prompt.setup()`. Multi-line templates are pasted with literal newlines (never
an implicit Enter).

A per-tool `format` hook (`cli.tools.<name>.format`, `fun(file, loc): string`)
spells each location reference as it is composed, so a tool can define its
dialect; the Agent now remembers its `cli.tools` key (`@agent-tool` window
option → `Agent.tool`) to look the hook up. This is the one place the location
syntax is tool-agnostic. A fifth placeholder, `{reviews}`, renders the
accumulated [Reviews](2026-09-01-reviews.md).

## Alternatives considered

### Why not unify `{function}` and `{class}` into `{symbol}`?

sidekick keeps them separate because they are different treesitter queries that
answer different questions (the enclosing method vs the enclosing class), even
though they render identically. A unified `{symbol}` would have to pick a rule
(innermost wins) and would lose the ability to disambiguate; matching sidekick
  exactly cost nothing here. Both were [later removed](../simplification/2026-09-11-remove-function-class-prompt-placeholders.md),
so the question is now moot.

### Why not a single global `format` hook?

A single `format(text, agent)` function would leave per-tool dispatch to the
user (a `switch` on `agent.cmd`). Hanging `format` on `cli.tools.<name>` and
persisting `@agent-tool` makes it automatic and matches sidekick's per-tool
model; the cost is one Agent field and one window option.

### Why not pass the Agent into `format`?

The hook's job is re-spelling a reference from its `file` and `loc` parts; the
Agent runs in the very cwd the path is relative to, so no re-relativization is
needed. A pure `fun(file, loc): string` is the smaller, more testable surface.

## Consequences

- `{a|b}` alternation, `{input}`, and `{selection}` are deliberately unsupported
  (not planned); static prompts are just templates with no placeholders.
  `{reviews}` is the one supported dynamic placeholder: it renders every
  accumulated Review (see the
  [reviews note](2026-09-01-reviews.md)). A built-in prompt library —
  originally unsupported here — now ships as the two identity defaults
  `{file}` and `{line}`.
- Location references are Claude-dialect (`@file :L10`); other tools are
  expected to translate via `format`. Superseded by
  [the Tool format hook note](2026-09-11-tool-format-location-hook.md):
  references are bare (`file` plus `loc`) and the hook spells the dialect.
- A future zellij driver can express `send_keys` via `zellij action write`, but
  that acts only on the focused pane (no pane id), so it would need an
  attached, focused client and would lose tmux's "send while hidden" property.

The Backend method it adds extends [the backend-driver-seam note](../architecture/2026-08-31-backend-driver-seam.md).
